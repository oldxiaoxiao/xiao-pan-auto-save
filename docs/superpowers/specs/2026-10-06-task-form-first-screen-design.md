# 新建任务表单的首屏与默认值设计

日期：2026-10-06 ｜ 状态：已与用户逐节确认 ｜ 前置：`2026-10-05-task-run-modes-design.md`、`2026-10-05-once-retry-budget-design.md`

## 1. 目标与出发点

用户（唯一使用者，追剧人）的原始问题：「新建任务这部分你从一个追剧人的角度，是否实用方便，适合简单配置使用以及复杂需求的使用」。

读完 `frontend/src/components/TaskForm.vue`、`backend/schemas.py`、`backend/core/engine.py` 之后，确认了七个**具体缺陷**（都有行号，不是泛泛的"可以更好"）：

| 编号 | 缺陷 | 出处 |
| --- | --- | --- |
| A | 「下载到本地」默认值前后端不一致：UI 新建为 `true`，后端/外部 API 省略字段时为 `false` —— 同一个动作两种结果 | `TaskForm.vue:49` vs `schemas.py:20` |
| B | 追剧最常见的一步（只抓剧集）藏在高级区，首屏提示反而教用户"去高级设置里填 `$TV`" | `TaskForm.vue:235-237` |
| C | **并列多目录分享**时，目录永远通过集数/画质过滤、整目录原样搬走；要过滤必须手写 `update_subdir` 正则 | `engine.py:201`（`passes = share_file.is_dir or matches_filters(...)`）、`engine.py:205` |
| D | 「起始集/结束集」与「起始文件 (startfid)」概念重叠、命名相近，看不出谁优先 | `TaskForm.vue:222-227` 与 `TaskForm.vue:309-318` |
| E | 「停用」在最底部高级区，而它的语义邻居「执行方式」在首屏 | `TaskForm.vue:373-376` |
| F | 没有"每部剧一个子目录"的默认，也没有预设，追 5 部剧要重复 5 次相同选择 | 现状即缺陷 |
| G | 保存前无法预知这一跑会搬什么；链接失效只能等到点运行后才知道 | 现状即缺陷 |

用户对本轮的四类痛**全部要点**（首次上手、重复劳动、复杂需求可达性、结果可预期），并确认了顺序：默认与首屏 → 概念合并与过滤诚实化 → 预设/复制 → 保存前试跑。

## 2. 非目标

- 不做多套命名预设（只有一份"新建任务默认"）。
- 不引入新的网盘专有逻辑，不改驱动接口。
- 不引入 vitest 等前端测试基建（仓库现状没有，本轮不为此新建）。
- 不改「执行方式」三态与一次性重试预算的既有语义（见前置 spec）。
- 不在后端偷偷给 `update_subdir` 设默认值（见 4.2 的理由）。

## 3. 决定清单（用户逐条选定）

| 议题 | 决定 |
| --- | --- |
| `auto_download` 默认 | **统一为开**：后端 `TaskIn.auto_download` 改为 `True`，与 UI 一致 |
| 保存路径默认 | **默认带剧名子目录**：`{savepath_root}/{剧名}`，剧名变则跟随，用户手改一次后不再跟 |
| 多目录分享的过滤陷阱 | **新建默认开目录内过滤**：前端在新建时显式带 `update_subdir=".*"`，首屏给人话开关，可关 |
| 起始集 / 起始文件 | **合并为一个概念**：首屏只留集数，`startfid` 降为"或从某个文件开始"的可选入口，并显示当前生效者 |
| 预设形式 | **一份全局默认 + 复制现有任务** |
| 保存前预览 | **保存按钮旁「试跑」**：只读、汇总 + 前若干条 |

## 4. 设计

### 4.1 首屏（7 项，填完即可保存）

1. 剧名（带智能搜索，不变）
2. 分享链接（+ 浏览，不变）
3. 保存路径 —— 默认 `/来自：分享/{剧名}`；`pathTouched` 标志控制"手改后不再跟随"——该标志在用户**手动编辑路径输入框**或**用「选择」按钮选定路径**时置真（程序代填剧名不置真），置真后剧名变化不再改路径；**编辑已有任务时永不自动改路径**
4. 抓取范围 —— 三选一：`全部文件`（`pattern=""`）/ `只抓剧集`（`pattern="$TV"`，就地显示 `$TV` 从 `magic_regex` 展开的真实正则）/ `自定义正则`。
   **`自定义正则` 不是第二个输入框**，而是一个动作项：展开高级区并把光标落到已有的 `pattern` 输入框上。首屏与高级区永远共用 `draft.pattern` 这一个状态，绝不出现两个框绑一个字段（否则谁覆盖谁又成一处的判定分叉）
5. 集数范围 —— `从第几集开始（含）` / `到第几集结束（含）`；小字入口「或从某个文件开始」→ 打开现有文件选择器的 `startfid` 模式。两者都设过时**起点以 `startfid` 为准**（`engine.py:245` 就是遍历到该 fid 即 `break`，集数过滤在其之后仍生效），选中后照此显示
6. 画质 —— 不变（4K/2160P 互为别名的说明保留）
7. 下载到本地 + 执行方式 —— 同一行；仅 `follow` 展开「更新频率」

紧随其后的开关：**`子目录也按集数/画质过滤`**（等价 `update_subdir=".*"`，新建默认开）。副文案：「填了起始集、结束集或画质时，分享里的文件夹会进去逐个文件比对；不填则整个文件夹原样搬走」。诚实提示：**子目录内的文件不参与魔法重命名**（`engine.py:208-210` 的既有行为，本轮不改引擎）。

「停用」：**新建表单不出现**（新任务无"暂停"语义；要等放出用「一次性」，要先存着不跑用「仅手动」）；编辑已有任务时移到「执行方式」旁，保留既有改形态提示。

高级区剩下：魔法重命名（pattern/replace + 变量插入 + 预览正则效果）、忽略扩展名、子目录重存模式、本地下载子目录、截止日期、指定账号、按星期。

**实现回写（Task 3 交付后）**：

- 「子目录内的文件不参与魔法重命名」**已核实为真**，语义如文档所述：`engine.py:224` 的入选分支里
  `if share_file.is_dir or rel_path:` 直接原样入队，`rel_path` 非空（即由递归比对进来的子目录文件）就不走
  `mr.sub(...)` 重命名。本轮未改引擎，故首屏开关的副文案按诚实提示写，文档与界面口径一致。
- 第 4 项「抓取范围」与本文有**一处偏离**，且偏离是对的：把「自定义正则」做成第三个 radio 选项后，它不写任何值，
  而档位本身是从 `draft.pattern` 派生的——点下去 `pattern` 不变、选中态立刻弹回原档，控件看着像坏了。
  现在 radio 组只承载两档真状态（`全部文件` = `""` / `只抓剧集` = `"$TV"`），`pattern` 是其它非空自定义值时
  返回一个不匹配任何选项的哨兵值，于是两档如实都不选中，旁边点名「当前是自定义正则」；进高级区的动作改成 radio
  旁的一条文字链接，仍只做展开 + 聚焦已有的 `pattern` 输入框。状态源依旧只有 `draft.pattern` 一个，没加第二个框也没加状态位。

### 4.2 后端默认与 `task_defaults` 设置键

- `TaskIn.auto_download: bool = True`。**破坏面**：外部 API / 油猴省略该字段建的任务从此会开始下载；README 与 `/api/add_task` 说明必须写。
- `TaskIn.update_subdir` 保持 `""`：目录内过滤的默认由**前端在新建时显式带 `".*"`**。理由是后端默认会静默改变所有调用方（含脚本批量建任务）的行为，而"每部剧一个目录、进去过滤"目前只是交互层的合理默认，不该变成协议层默认。
- 新设置键 `task_defaults`（进 `api/deps.py` 的 `DEFAULT_SETTINGS` 与 `api/routes_settings.py` 的 `EDITABLE_KEYS`，**不新增端点**，沿用通用 `PUT /api/settings/{key}`）。只装 6 项：

```
savepath_root   默认 "/来自：分享"
auto_download   默认 true
run_mode        默认 "follow"
pattern         默认 ""（空=全部文件，"$TV"=只抓剧集，其余=自定义）
quality         默认 ""（不限）
subdir_filter   默认 true（前端据此决定是否带 update_subdir=".*"）
```

- 生效顺序：后端字段默认 → `task_defaults` 覆盖 → 用户本次手改。**只作用于新建**，绝不回写已有任务。
- `savepath` 组装：`{savepath_root}/{taskname}`；`taskname` 为空时不拼（留 root）。

### 4.3 复制为新任务

列表行「⋮」菜单加一项「复制为新任务」，复用现成的 `pendingPrefill` 通道（智能搜索建任务已走这条路）。带出全部业务字段，**剥掉**：`id / disabled / shareurl_ban / last_run_at / retry_attempts / next_retry_at / sort_order / startfid`。

- `startfid` 必须剥：它是分享内的 fid，复制到别的分享毫无意义，留着会静默截断转存范围。
- `sort_order` 交给"新建置顶"（复用 `above_sort_order`）。
- 剧名原样带出，不自动加"副本"后缀；若与已有任务同保存路径，表单顶部提示：`这条任务和已有任务用了同一个保存路径，同名文件会被认成"已存在"而跳过`。

### 4.4 试跑（dry-run）

**不给判定写第二套实现。** 真实运行的决定全在 `engine.py::_check_dir`：单文件夹下钻（`engine.py:154-160`）、`pattern`/`update_subdir` 匹配、`matches_filters`（`engine.py:60`）、`is_exists` 已存在识别、魔法重命名与 `{I}` 递增、递归、`startfid` 截断（`engine.py:245`）。其中混着三类写操作：`ensure_dir`（`engine.py:193`）、重存时的 `delete_items`（`engine.py:220`）、转存 `driver.save`（`engine.py:261`）与其后的 `rename`。

决定：给引擎加一个参数

```
run_update_task(driver, spec, magic_regex=None, log=None, plan_only: bool = False)
```

`plan_only=True` 时：跳过 `ensure_dir`、跳过 `delete_items`、跳过 `driver.save`/`rename`；目标目录列不出来就按"目录不存在 = 全部算新增"处理（与真实运行的 `dir_names=[]` 降级同口径）；把 `_Plan` 直接落成 `result.files`（`new_fid=""`，`dest_path` 照常算）；`status` 的置法明确为：**有任何计划条目即 `"updated"`，一条都没有则保持默认的 `"no_changes"`**（与真实运行在 `_check_dir` 末尾置 `updated` 的时机等价）。真实运行的代码路径语义不变。

**新端点** `POST /api/tasks/dry-run`：收一份 `TaskIn`（**不需要已存在的任务行**），按 `account_id` 取驱动（为空则复用 `task_service._pick_account` —— 与真实运行同一个选号函数，不另写一套），**不写库、不占 `_run_lock`**（只读），返回汇总 + 前 20 条：

```
会新增 4 项 · 约 4.1 GB · 落到 /来自：分享/择日飞升
已存在跳过 26 项 · 被集数/画质过滤 3 项
27.4K.SDR.mp4（会新增）  01.4K.SDR.mp4（已存在） …
```

链接失效 / 需要提取码 / 网络异常，直接在这里按既有的 `banned` / `failed` / `network` 分类报出来，不用等到点运行才知道。

**不自动触发**：每次试跑都是真的访问网盘（递归目录可能十几秒），只在用户点「试跑」时执行；按钮文案明写「试跑（只读：不转存、不下载）」。

**与现有「预览正则效果」不合并**：后者在文件选择器里，回答"这条正则把名字改成什么样"；试跑回答"这一跑会新增哪些文件"。两个目的、两个名字都保留，标签写清区别。

### 4.5 文案（逐字）

| 位置 | 文案 |
| --- | --- |
| 抓取范围 | `全部文件` / `只抓剧集` / `自定义正则`；只抓剧集的说明：`只挑剧集文件，跳过特典、字幕、说明之类别的内容` |
| 目录内过滤 | 标题 `子目录也按集数/画质过滤`；副文案 `填了起始集、结束集或画质时，分享里的文件夹会进去逐个文件比对；不填则整个文件夹原样搬走`；提示 `子目录内的文件不参与魔法重命名` |

## 5. 破坏面（必须写进 README，不能只说"改进"）

1. `TaskIn.auto_download` `False → True`：省略该字段的外部调用方会开始下载。
2. 新建任务默认带 `update_subdir=".*"`：对并列多目录分享是**新行为**（进去逐文件过滤，而非整目录搬走）。已有任务不变。
3. 新建表单不再提供「停用」：需要"先存着不跑"请用「仅手动」，"等放出"请用「一次性」。
4. `blank()` 与后端默认终于一致，A 项分歧点消失。

## 6. 测试

后端（`.venv/bin/python -m pytest backend/tests -q`，基线 317 passed + 1 skipped）：

- **试跑与真实运行结果相等**（本设计的承重测试）：同一份假盘目录树，先 `plan_only` 取"会转的集合"，再真跑一次（假盘、零网络），断言两个集合**完全相等**。相等性比较的键明确为 `(final_name, dest_path)` 组成的多重集——**不比整个对象**，因为 `plan_only` 拿不到 `new_fid`（它由驱动转存后才产生）。以后谁改了过滤/去重而没同步试跑，这条就红。
- `plan_only` 下 `ensure_dir` / `save` / `delete_items` / `rename` **零调用**（计数桩断言）。
- 并列多目录分享：`update_subdir=".*"` 时进入目录并逐文件过滤；`""` 时整目录原样通过（钉住 C 项的真实语义，防止被误称"已修复"）。
- `TaskIn.auto_download` 默认 `True` 的回归 + 外部 `add_task` 省略字段时的行为断言。
- `task_defaults`：读写、默认值、以及"只作用于新建"（已有任务 PUT 不受 `task_defaults` 影响）。
- `dry-run` 端点：无任务行也能跑；不写库（前后任务表快照一致）；`banned`/`network` 分类如实返回。

前端：`npm run typecheck` + `npm run build`；无 vitest，行为靠真机取证。

真机验收（库副本 + 隔离端口，绝不动用户的 8432/5173/6800；真实账号仅在需要真实分享的条目上使用，且默认假盘）：

1. 只填剧名 + 链接 → 路径自动成 `/来自：分享/{剧名}`，保存即建。
2. 改剧名 → 路径跟；手动改一次路径 → 不再跟。
3. 切「只抓剧集」→ 就地显示 `$TV` 展开的正则。
4. 「或从某个文件开始」→ 选文件后显示当前生效起点。
5. 「试跑」对已全部转存的分享 → `会新增 0 项 · 已存在跳过 N 项`，且**跑完网盘目录没有任何新文件**（列目录前后对比自证只读）。
6. 「试跑」对一个新分享 → 汇总数字与随后真实运行日志的"新增 N 项"一致。
7. 「复制为新任务」→ 业务字段带出，`startfid`/停用/失效标记/计数字段不出现。
8. 设置页改「新建任务默认」→ 下一个新建任务生效，已有任务不变。

不能验证的明确写 `NOT VERIFIED + 原因`。
