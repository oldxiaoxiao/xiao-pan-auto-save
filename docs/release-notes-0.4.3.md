# 小盘自动转存 0.4.3 · 任务页点击：找到 Windows 上的真凶

> v0.4.2 修的是"点了之后没有任何反馈"的**提示问题**；这一版修的是 Windows 客户端上
> **点击压根没有发生**的问题——两者表现一样（点了没反应），根因完全不同。

## 真凶：整行可拖拽，点击被内核吃掉了

任务列表的每一行此前整体带着 `draggable="true"`（为了拖拽排序）。在 Windows 客户端的
WebView2（Chromium 内核）里，按下鼠标后**手抖几个像素**就会被判定为"开始拖拽"，
于是浏览器不再派发 `click`：

- 点任务行 → 行不展开
- 点「＋ 新建任务」→ 同样没反应（拖拽会话未正常结束时，窗口内的鼠标事件都会被吞）

这就是"点什么都没反应"的来源。**macOS 上不容易出现**（WKWebView 的拖拽阈值与判定不同），
也是为什么上一版在 macOS 上验证通过、你的 Windows 上却依旧如此。

改法：**拖拽只挂在行首那枚手柄上**（序号左边的 `⋮⋮`，鼠标移上去是抓手光标），
行主体永远只是点击。排序功能没丢，只是起步的位置明确了。

| | 之前 | 现在 |
|---|---|---|
| 拖拽起点 | 整行任意位置 | 行首那枚手柄 |
| 点击行主体 | 可能被判成拖拽，click 不来 | 永远是 click |
| 拖拽排序 | 可用 | 可用（按住手柄上下拖） |

## 另外两道兜底

1. **存储不再能拖垮界面**：「上次选的搜索引擎」这个偏好存在 `localStorage` 里，
   而原生 WebView 的存储可用性由内核和隐私模式说了算——一旦抛错，任务表单整个渲染不出来，
   又是"点了没反应"。现在读不到就当没选过，写不进就只在本轮会话里记着，绝不抛错。
2. **界面错误从此看得见**：新增左下角的**错误条**。此前 Vue 只把渲染错误打到控制台，
   而打包后的客户端没有控制台可开，一个组件渲染失败就变成"从此点什么都没反应"、**没有任何线索**。
   现在错误会登记下来：底部显示条数，点「详情」展开原文，点「复制」直接复制，
   便于把原文发给我定位。

## 验证

- 真实 pywebview 窗口 + 生产构建实测（DOM 级）：
  - `dragwrap[draggable]` 数量 **0**，行首手柄 `draggable` 数量 = 任务数 —— 结构性修复到位；
  - 点击行主体仍能正常展开（回归通过）；
  - 注入一个错误后，左下角错误条出现并显示"界面出现 1 个错误"，可展开可复制。
- 前端 typecheck / lint:check **0 error** / prettier 全过；
  后端 ruff 通过、`TZ=UTC pytest` **664 passed / 1 skipped**。

## 已知边界（必须说清楚）

- **这次的修复我只能在 macOS 上验证，无法在 Windows 上复现**——触发它的是真实鼠标的
  微小位移，脚本点击模拟不出来，而开发环境这边没有 Windows。
  改的是结构性成因（行不再可拖），理论上与内核无关，但**需要你在 Windows 上确认**。
- 如果仍有问题，**请看一下左下角的错误条**：点「详情」展开、点「复制」把原文发我。
  这条通道就是为"我复现不了、你又说不清"这种情况准备的。
- 前端依旧没有自动化测试框架，这类交互回归 CI 防不住。

## 升级注意

1. 只改前端交互与错误处理，未动表结构与接口，升级向下兼容。
2. 桌面端仍是"下载新包 → 替换程序"，数据目录不受影响。
3. 拖拽排序改用手柄：搜索/筛选状态下手柄会隐藏（与之前一致，那时排序暂不可用）。
