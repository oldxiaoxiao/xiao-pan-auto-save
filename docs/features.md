## 功能范围

当前仅夸克驱动可用。公共搜索源可用性、账号 Cookie 和通知渠道需要自行验证；自动测试通过不能保证第三方服务始终可达。


- 🔌 **驱动抽象层**：任务按分享链接域名自动路由网盘驱动，加一个网盘 = 加一个文件
  （教程见 [驱动开发](drivers.md)）。当前已支持 **夸克网盘**，
  迅雷 / 123 / 百度 / 阿里 / 115 / 天翼 / 移动 / AList 驱动骨架已就位（尚未实现）。
- 🔄 **追更引擎**：分享列表与目标目录差集比对只转新增；忽略扩展名去重（`01.mp4≈01.mkv`）；
  起始文件订阅（跳过老集数）；子目录追更（递归比对 / 删除重存两种模式）；链接失效自动标记并通知。
- ✨ **魔法重命名**：正则 + 替换式，内置 `$TV` 等魔法关键字与 `{TASKNAME} {SXX} {E} {II} {DATE}`
  等变量；`{II}` 依目标目录现状自动递增编号。
- ⏰ **调度**：APScheduler 全局 crontab + **任务级独立频率**（每 N 分钟 / 每周某天 / 自定义 cron），
  外加任务级 runweek（星期）/enddate（截止）过滤；转存阶段全局串行、下载阶段并行。
- 🎛 **执行方式三态**：**定时追更**（默认，按频率或全局 crontab 自动跑）/ **仅手动**（永不自动触发）/
  **一次性**（每天看一次等它放出；拿到新增且本地下载全部成功后**自动停用**，列表显示「已完成」）。
  一次性的重试口径：资源还没放出**不算失败、不占预算**；真失败（转存炸了、链接失效、或下载有失败项）
  最多重试 **3 次、每次间隔 5 分钟**，用尽后停摆并显示「重试已用尽」，点该行「▶ 运行」重新给三次预算
  （停摆**不会**把任务置为停用）。
  分工：**执行方式决定要不要自动跑，「停用」决定要不要临时暂停一切**。
- 🚫 **批量「立即运行」跳过已停用任务**（汇总里给出跳过条数）；行内「▶ 运行」对停用行仍可用，便于手工重试。
- 🎯 **新建任务三填即建**：首屏只有**任务名称/智能搜索、分享链接、保存路径**三项必填。填上剧名后保存路径自动
  拼成 `保存路径根/{剧名}`（你手改过一次路径就不再跟随）；抓取范围（`全部文件` / `只抓剧集 $TV`）、起始集/结束集、
  画质这些常用口径也在首屏，正则、魔法变量、子目录追更、起点文件仍收在**高级设置**里。新建时的初值来自设置页的
  **「新建默认」**（全局一份，只影响以后新建的任务，绝不回写已有任务）；行内「⋮ → 复制为新任务」带出来源行的
  业务字段，其中 `startfid` 会被剥掉——它属于来源那条分享，留着会静默截断新任务的转存范围。
- 🧪 **保存前「试跑」**：表单里的「试跑」走只读路径（`POST /api/tasks/dry-run`），**不转存、不下载、不建目录、
  不占运行锁**，且判定与真实运行共用同一套引擎代码——云端内容没有变化时，预览与真实执行使用相同筛选判据。
- 📣 **通知**：实现 24 种通知渠道协议（Web 设置表单提供常用渠道，其余可通过配置 API 写入）（Server酱 / PushDeer / Bark / 钉钉 / 飞书 / Telegram /
  企业微信 / ntfy / 自定义 webhook 等 24 渠道），运行结果树形摘要聚合推送。
- 📥 **下载到本地**：转存成功的新文件可自动落盘——内置流式下载器（.part 临时文件保护（不支持跨重启断点续传）、目标已是
  **验证过的完整文件**才跳过、并发控制、目录镜像/平铺）或投递 **Aria2 RPC**（协议兼容原项目，
  支持暂停模式；投递前用同一份判据预检：完整文件不重下，失败/中断留下的预分配残骸照常重投）；下载完成后可自动
  触发 **Emby 媒体库刷新**。任务级"下载到本地/递归子目录"开关。每次下载都落一条 **历史账本**
  （状态、体积、目标路径、是否到位），失败的单文件可直接重下，见下文[下载历史与失败重下](#下载历史与失败重下)。
- 🖥 **Web 管理**：任务卡片 + 展开编辑 + 星期胶囊；智能搜索建议（出厂预设**两个公开源互为备份**：
  **PanSou 公共站 so.252035.xyz** 与 **夸克搜 kkso.net**，都不需要配置即可搜；每种协议还能再配多个实例，
  `CloudSaver` 属自建协议——官方不提供在线 Demo 且明确反对使用他人实例，请自建后填地址）。
  默认把所有启用的引擎一起搜，重复分享链接合并成一条并标注来源，建任务时搜索框前的下拉可切到单引擎、
  验证链接、点选建任务；文件选择器带面包屑、**分享目录树可逐层下钻浏览**与正则处理效果实时预览；
  SSE 实时运行日志；多账号管理。
- 🧭 **任务排序**：新建任务自动排在列表最前（网页表单和油猴 `/api/add_task` 都走这条规则，
  不随拖拽历史漂移），行内「⋮」菜单可 **置顶 / 置底**，也支持整列表拖拽排序。
- 🧩 **API 与油猴脚本**：Token 鉴权的 `/api/add_task`（兼容旧格式）与 `/api/v1/task/*`，
  附重写好的油猴脚本（`scripts/xiao-pan-auto-save.user.js`）：夸克分享页一键加任务。


## 下载历史与失败重下


下载页分 **进行中 / 历史** 两个 tab：进行中只看实时在跑的任务（内置 + aria2 活动队列，1.5s 刷新），
历史则是写进 SQLite 的下载账本——一条记录 = 一次下载动作的完整生命周期，重启后端也不丢。

- **筛选与分页**：按状态（排队/下载中/完成/失败/跳过/已停止，可多选）、按任务、按文件名或目标路径
  关键词过滤，默认每页 50 条。关键词按字面匹配（`100%` 不会被当成通配符）。
- **`文件` 列（到位校验）**：每次查询历史时对当页**终态**记录的目标路径做一次 `stat`——
  **在** = 常规文件在、大小与账本相符，且没有 `<name>.aria2` 控制文件、也不是稀疏预分配（账本没记
  大小时只说明"文件在"，不作为完整凭据）；**不完整**（partial）= 常规文件在但大小与账本不符，或
  带着 aria2 的控制文件/只有预分配的大小没有实际字节（截断、失败残留）；**已丢失** = 路径上已经没有
  这个文件；**未校验** = 非终态行（在途下载不做"到位"判断——aria2 会先建整片大小的预分配占位文件，
  "在"不代表下完了，活体翻车点）或读不到（权限异常、挂载丢失、路径是目录），不当成丢失，避免把
  "暂时看不了"误报成"文件没了"。
- **单文件重下**：历史任意一行点「重下」，后端**重新取一次直链**（老直链会过期），沿用记录里的
  fid + 账号（账号被删/停用则回落到该网盘可用的主账号），并**打回原来的目标路径**
  （`dest_path` 原样，不受后来改动下载根目录/覆盖路径的影响）。**两种下载模式共用同一份到位判据**
  （`download_history._file_check`，全项目唯一一处 stat 解读）：只有**验证过的完整文件**才记为**跳过**、
  不重复占盘；大小未知（账本没记大小）、大小不符、aria2 预分配残骸（整片大小的稀疏文件、旁边还留着
  `<name>.aria2`）都当"没验证过"→ **重新下**，所以点几次重下都会往前收敛，不会出现"永远跳过、
  永远修不好"的文件。aria2 模式在 `addUri` 投递**前**做这项预检——缺了它，daemon 对已存在的同名文件
  不改写而是自动改名（`S01E194.1.mkv`）重下整片 3.5GB，账本还停在原路径（活体翻车点）。一次尝试新增
  一行，旧记录不改写，方便看出第几次才成功。立即返回的提示只代表"已开始"，内置下载器一个 4K 文件
  可能跑几小时。
- **下载根目录的绝对化**：读取设置时把 `dir` 归一化为绝对**字面**路径（相对值按后端进程工作目录解析，
  如 `data/downloads` → `<仓库路径>/data/downloads`），账本 `dest_path` 与 aria2 `addUri dir` 都用它，
  到位校验与重下不再依赖服务端 CWD。带软链的挂载路径只补绝对、不展开 realpath（见 b1d156b），
  修复前落库的相对路径旧行仍按原字面路径校验。
- **aria2 的终态**：aria2 完成后从活动队列消失，因此历史页每次查询时对未完成记录做一次对账——
  逐个 gid 问 `aria2.tellStatus`（真 aria2 没有 `tellDownloadResult`，`system.multicall` 也不接受带 token 的子调用），
  `complete` 判**完成**、`error`/`removed` 判**失败**并带上 daemon 给的理由；问不到（gid 已被丢弃、RPC 不可达）
  再看目标是不是**验证过的完整文件**（同一份 `_file_check` 判据：大小相符、无 `.aria2` 控制文件、非稀疏占位），
  只在下载真的收尾后收口——在途作业的那份预分配占位绝不被当成完成；两者都确认不了的，24 小时内的记录保持
  `排队/下载中`，超过 24 小时判为 `失败`（对账超时），避免后端重启后遗留的记录永远挂着。
- **保留策略与清理**：设置 → 下载设置里的「历史保留」可选 最近 30/90/180 天或永久保留（默认 90 天）。
  过期终态记录由调度器**启动时 + 每天**自动清理（只删记录，绝不动磁盘上已下载的文件）。历史页的
  「清理」下拉还支持手动操作：按保留策略清理 / 只清失败记录 / 清空全部，均需二次确认，清理结果以
  "已清理 N 条"回显。

三点如实说明的边界：

1. **账本只记录真正开始的下载**：写库点在"取到直链、开始下载"之后，所以转存成功但**取直链失败**、
   驱动不支持下载、aria2 投递失败这类前置失败不会出现在历史里，只能在任务的运行日志中看到。
   同一路径的并发重下由**两层守卫**拦截：账本里该路径还有未收口的行时，「重下」直接返回 409；
   而"取直链窗口"里账本行尚未写入，这期间的第二次点击由**进程内**的同路径在途登记兜住，被拦的
   尝试不落账本、不碰正在写的文件。在途登记只活在单进程内（本项目默认单 uvicorn worker），跨进程并发不在拦截范围；
   **两种下载模式都受这层守卫**——aria2 提交窗口同样先登记再投递，投递 RPC 返回、queued 行落下即释放。
   这不能不拦：aria2 daemon 对同路径重复投递不去重，而是撞名自动改名（活体实证：连点两次重下，
   真下了两份 3.5GB 整片，第二份落成 `S01E194.1.mkv`）。
2. **aria2 排队很深的记录可能晚点才对账**：进行中列表只取 `tellWaiting` 的前 200 条，排在 200 条之后的
   作业既不在活动队列、结果也还没产生，只能等它进入前 200 条或文件到位后才被确认；超过 24 小时仍未
   确认的会按上面的规则收口成失败。
3. **到位判据一律倒向"宁可重下"**：`<name>.aria2` 控制文件还在、或 `st_blocks * 512 < st_size`（预分配
   了大小却没真写满）时判「不完整」并重新下。两个已知偏差都只往多下的方向倒，不会反过来把没下完的
   文件认成成品：① 内置下载器接管 aria2 中断留下的残骸时，不会替 aria2 删那个控制文件，该行会一直
   显示「不完整」并每次重下（aria2 自己收尾时会删，正常路径不留残留）；② 块数报不准的挂载（个别
   FUSE/CIFS、透明压缩的 btrfs）可能把完整文件读成稀疏，同样退化成重下。


## 内置下载与 Aria2 的差异

| 操作 | 内置下载 | Aria2 RPC |
|---|---|---|
| 下载/实时进度/历史/单文件重下 | 支持 | 支持 |
| 停止 | 支持 | 支持 |
| 暂停/继续 | 不支持 | 支持 |
| 断点续传 | 不支持；重试重新下载 | 由 Aria2 控制文件和配置决定 |
| 服务依赖 | 无额外下载服务 | 需部署 Aria2 并对齐路径 |

清理历史和删除下载条目不会自动删除已下载的文件。文件到位检查是大小、控制文件和磁盘分配校验，不是内容哈希验证。

## API 与浏览器脚本

在设置 → API 创建 Token，完整值只在创建时显示。安装仓库 `scripts/xiao-pan-auto-save.user.js`，配置服务地址和 Token 后可在夸克分享页添加任务。客户端每次启动使用随机端口，0.1.1 不提供稳定的油猴连接地址；有此需求请使用 Compose 版。

管理 API 使用网页登录会话或 HTTP Basic；外部 API 使用独立 Token，两者不能互相代替。Token 支持查询参数和 `Authorization: Bearer`，推荐后者。

| 路径 | 方法 | 用途 |
|---|---|---|
| `/api/add_task`、`/api/v1/task/add` | POST | 兼容格式添加任务 |
| `/api/v1/task/list`、`/api/tasklist` | GET | 查询任务 |
| `/api/v1/task/update` | POST | 更新请求中出现的字段 |
| `/api/v1/task/run` | POST | 按 id/名称运行；未指定时运行全部 |
| `/api/tasks/dry-run` | POST | 管理界面只读试跑 |

管理 API 的 `PUT /api/tasks/{id}` 是整行替换，省略字段按默认值补齐；需要部分更新时使用外部 update 接口。
