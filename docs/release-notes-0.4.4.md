# 小盘自动转存 0.4.4 · 任务表单崩溃的真凶：emoji 被当成组件标签

> 这是"任务页点了没反应"的**第三个**根因，也是真正导致表单渲染失败的那一个。
> v0.4.2 修了提示被静默吞掉、v0.4.3 修了整行可拖拽吞掉点击；这一版修的是
> **任务表单在渲染时直接抛异常**——前两版都没白改，但都不是你在 Windows 上遇到的那一个。

## 真凶：`:icon="'🔍'"`

任务表单里「浏览」和「选择」两个按钮，此前是这么写的：

```vue
<el-button :icon="'🔍'" ...> 浏览 </el-button>
<el-button :icon="'📁'" ...> 选择 </el-button>
```

Element Plus 的 `icon` 属性要的是**组件对象**（如 `@element-plus/icons-vue` 里的 `Search`），
传字符串会被 Vue 当成"用这个标签名创建元素"，也就是执行 `document.createElement('🔍')`。
在部分 Blink 内核（Windows 客户端使用的 WebView2 运行库）上，这行直接抛：

```
InvalidCharacterError: Failed to execute 'createElement' on 'Document':
The tag name provided ('🔍') is not a valid name.
```

**整个 TaskForm 因此渲染失败**。于是：点「＋ 新建任务」→ 表单出不来 → 看起来毫无反应；
点任务行 → 详情出不来 → 同样毫无反应。这就是你报的"I怀疑是任务详情展示方式有问题"。

### 为什么我前两版在 macOS 上怎么点都正常

| 内核 | `document.createElement('🔍')` |
|---|---|
| macOS 客户端（WKWebView / WebKit） | 返回 `HTMLUnknownElement`，**不抛错** |
| Windows 客户端（WebView2 旧运行库） | 抛 `InvalidCharacterError`，表单死掉 |

实测记录：同一份**含此 bug 的构建**，在 macOS 真实客户端里表单照常渲染（25 个输入框、
22 个按钮齐全），所以本机永远复现不出来。内核允许"非法标签名"的程度不同，这就是全部原因。

**这一版之所以能定位，靠的正是 v0.4.3 加的左下角错误条**——它把 Windows 上的原始堆栈照了出来，
你贴的那一行（`createElement ('🔍')`）直接指向了代码里的字符串。兜底通道起了作用。

## 修法

- 两个按钮改为把 emoji 作为**按钮文本**（`🔍 浏览` / `📁 选择`），不再走 `icon` 组件属性；
  外观基本不变，行为完全不变。
- **加一道 CI 守卫**：`frontend` 的 verify 任务里新增一步，扫描所有 `.vue` 中的
  `:icon="'...'"` 写法并让流水线失败。这类"字符串当组件"的错误以前只会在某个内核上
  运行时爆、静态检查看不出来，现在提交前就会被拦。

## 验证

- 真实 pywebview 客户端 + 生产构建实测：点「新建任务」后 `.form` 存在、**25 个输入框 / 22 个按钮**、
  7 个字段标签齐全，错误条**不存在**（不再有渲染错误）。
- 点「📁 选择」→ 弹出「选择保存目录」对话框，错误条仍为空（改动未破坏点击）。
- 前后对照：把源码临时切回有 bug 的版本重新构建，同一套探测在 macOS 上依然通过
  ——**证明确实是内核差异，不是我的探测方式有问题**。
- CI 守卫自测：干净源码放行（exit 0）；插入 `:icon="'🔍'"` 的临时文件被拦下（exit 1），
  而合法的 `:icon="Search"` 不误伤。
- 前端 typecheck 通过、lint:check **0 error**、prettier 全过。

## 已知边界

- 该 bug 的**抛错行为**无法在本机复现（WebKit 不抛），修复依据是 Windows 端的真实堆栈 +
  代码里唯一的两处 emoji 字符串 icon，二者一一对应。仍需你在 Windows 上点一下确认。
- 前端没有自动化测试框架，交互回归 CI 覆盖不到；但这次的成因（字符串 icon）已被 CI 守卫覆盖。
- v0.4.3 的拖拽手柄改造保留：它是真实的输入层隐患，只是不是本次症状的原因。

## 升级注意

1. 只改前端模板与 CI 配置，未动接口与表结构，升级向下兼容。
2. Windows 用户请下载 `xiao-pan-auto-save-0.4.4-windows-x64-aria2.zip`（完整版）或精简版替换程序。
3. 若替换后仍有异常，请打开左下角错误条 →「详情」→「复制」，把原文发出来。
